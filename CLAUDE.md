## Project

SwiftUI + Core Data starter app (`TodoListTest`) generated from Xcode's "App with Core Data" template. Swift 5.0, deployment target iOS 26.2; `SDKROOT = auto` with `SUPPORTED_PLATFORMS = "iphoneos iphonesimulator macosx xros xrsimulator"` — the same target builds for iOS, macOS, and visionOS, so platform-specific UI must be guarded (see the `#if os(iOS)` around `EditButton` in `ContentView.swift`).

No Swift Package or CocoaPods dependencies; everything is driven by `TodoListTest.xcodeproj`.

## Build & test

Use `xcodebuild` from the repo root. Scheme name matches the project: `TodoListTest`.

```sh
# Build for iOS simulator
xcodebuild -project TodoListTest.xcodeproj -scheme TodoListTest \
  -destination 'platform=iOS Simulator,name=iPhone 15' build

# Run all tests (unit + UI)
xcodebuild -project TodoListTest.xcodeproj -scheme TodoListTest \
  -destination 'platform=iOS Simulator,name=iPhone 15' test

# Run a single test (Class/Method)
xcodebuild -project TodoListTest.xcodeproj -scheme TodoListTest \
  -destination 'platform=iOS Simulator,name=iPhone 15' \
  -only-testing:TodoListTestTests/TodoListTestTests/example test
```

`TodoListTestTests` uses the Swift Testing framework (`import Testing`, `@Test`). `TodoListTestUITests` uses XCTest + `XCUIApplication`.

## Architecture

Three Swift files plus the Core Data model:

- `TodoListTestApp.swift` — `@main` App. Constructs the singleton `PersistenceController.shared` and injects its `viewContext` into the SwiftUI environment via `\.managedObjectContext`.
- `Persistence.swift` — `PersistenceController` wraps an `NSPersistentContainer(name: "TodoListTest")`. Two entry points:
  - `.shared` — on-disk store used by the app.
  - `.preview` — `inMemory: true` (store URL set to `/dev/null`), seeded with 10 `Item`s for SwiftUI previews. Marked `@MainActor`.
  - `automaticallyMergesChangesFromParent = true` is set on the view context.
- `ContentView.swift` — drives the UI off a `@FetchRequest` of `Item` sorted by `timestamp`. Mutations (`addItem`, `deleteItems`) go through the environment's `viewContext` and call `viewContext.save()` directly; errors currently `fatalError` (template code — replace before shipping).
- `TodoListTest.xcdatamodeld` — single entity `Item` with one optional `Date` attribute `timestamp`. `codeGenerationType="class"` means the `Item` NSManagedObject subclass is generated by Xcode at build time; do not add a hand-written `Item.swift`.

The data flow is intentionally minimal: SwiftUI view ⇄ `@FetchRequest` ⇄ `viewContext` ⇄ `NSPersistentContainer`. There is no view-model layer, no repository, no async work — keep new features consistent with this pattern unless deliberately introducing one (and, per the user's global instruction, don't introduce architecture not asked for).

## Conventions worth knowing

- The Core Data model name `"TodoListTest"` in `Persistence.swift` must match the `.xcdatamodeld` filename — rename both together.
- `ContentView` is also the macOS/visionOS entry — wrap UIKit-only modifiers in `#if os(iOS)` as the existing `EditButton` does.
- Previews depend on `PersistenceController.preview`; if you add required Core Data attributes, update the preview seed loop or previews will crash.
